# RSA

RSA (Rivest, Shamir, Adleman, 1977) rests on the **factoring problem**: multiplying two large primes is easy; recovering them from their product isn't.

## Key generation

1. Choose two large random primes $p$ and $q$ (1536 bits each for a 3072-bit key).
2. Compute $n = pq$ and $\varphi(n) = (p-1)(q-1)$.
3. Choose the public exponent $e$, almost always $65537 = 2^{16} + 1$, with $\gcd(e, \varphi(n)) = 1$.
4. Compute the private exponent $d = e^{-1} \bmod \varphi(n)$ with the extended Euclidean algorithm.

The public key is $(n, e)$. The private key is $d$ (plus $p$ and $q$, for speed).

## Encryption, decryption, signatures

$$
c = m^e \bmod n, \qquad m = c^d \bmod n
$$

$$
s = h^d \bmod n, \qquad \text{verify: } s^e \bmod n \stackrel{?}{=} h, \quad h = H(\text{message})
$$

## Why it works

Since $ed \equiv 1 \pmod{\varphi(n)}$, we have $ed = 1 + k\,\varphi(n)$ for some integer $k$. For $m$ coprime with $n$, Euler's theorem gives

$$
c^d = m^{ed} = m^{1 + k\varphi(n)} = m \cdot \left(m^{\varphi(n)}\right)^k \equiv m \cdot 1^k = m \pmod n
$$

(It also holds when $m$ shares a factor with $n$, which you can show modulo $p$ and $q$ separately, using the CRT.)

## Why it's secure (as far as we know)

Computing $d$ requires $\varphi(n)$, which requires $p$ and $q$. Knowing $\varphi(n)$ and $n$ gives $p + q = n - \varphi(n) + 1$, and then $p$ and $q$ are the roots of a quadratic. The best known factoring algorithm, the general number field sieve, runs in time

$$
\exp\!\Big( (1.923 + o(1)) \, (\ln n)^{1/3} (\ln \ln n)^{2/3} \Big)
$$

That's sub-exponential, which is why RSA needs 3072-bit moduli for 128-bit security. The record factorization is RSA-250 (829 bits, in 2020).

## Textbook RSA is insecure

The raw formulas above, called **textbook RSA**, fail in three ways that the script demonstrates:

1. **Deterministic**: the same $m$ always gives the same $c$, so an attacker encrypts guesses and compares. It's not IND-CPA.
2. **Malleable**: $c_1 c_2 = m_1^e m_2^e = (m_1 m_2)^e$. The attacker multiplies plaintexts without the key: `E(1000) * E(3)` decrypts to `3000`.
3. **Small messages**: with $e = 3$ and $m^3 < n$, the ciphertext is just $m^3$, and an ordinary cube root recovers $m$.

## Real RSA uses padding

| Use | Scheme | What it adds |
|---|---|---|
| Encryption | **RSA-OAEP** | random padding through a Feistel-like structure with hashes: randomized and non-malleable (IND-CCA2) |
| Signatures | **RSA-PSS** | randomized padding, with a security proof |
| Legacy | PKCS #1 v1.5 | still common; v1.5 *encryption* enabled Bleichenbacher's padding-oracle attack (1998), which keeps returning (ROBOT, 2017) |

The end of `toy-rsa.js` uses Node's real RSA: OAEP gives different ciphertexts for the same message, and PSS signatures verify.

## RSA today

RSA remains everywhere in certificates and signatures, but it's being displaced:

- TLS 1.3 **removed RSA key transport** (encrypting the session key with the server's RSA key), because it had no forward secrecy, and kept RSA only for signatures.
- Elliptic curves give the same security with much smaller keys and faster signing.
- RSA, like all classical public-key cryptography, will be broken by a large quantum computer (chapter 6).
