# The brand color and color harmonies

## Choosing the brand color

The brand color is usually given (a logo exists). When it isn't, choose with these in mind:

- **Associations**: blues read as trustworthy and calm, which is why finance and productivity tools use them so often. Greens suggest growth and health, and oranges energy. Associations differ between cultures, so test them with your users.
- **Distinctiveness**: look at your competitors' colors.
- **Conflicts with meaning**: a red brand makes every primary button look like a delete button. A green one competes with success messages. Blues, indigos, violets and teals are the safest choices for apps.
- **Range**: you need versions dark enough for text on white ($\mathrm{CR} \ge 4.5$) that still read as the brand. Bright yellow brands struggle here: a yellow dark enough for text turns olive or brown.

This chapter uses an indigo, `#4f46e5`, which in OKLCH is $L = 0.511$, $C = 0.230$, $h = 277^\circ$.

## Harmonies are rotations of the hue

Classic color harmonies are rotations on the color wheel. In OKLCH they are a single formula:

$$
h_k = (h_0 + \Delta_k) \bmod 360^\circ
$$

| Harmony | Offsets $\Delta_k$ |
|---|---|
| Analogous | $\pm 30^\circ$ |
| Complementary | $180^\circ$ |
| Split complementary | $180^\circ \pm 30^\circ$ |
| Triadic | $\pm 120^\circ$ |
| Tetradic (square) | $90^\circ, 180^\circ, 270^\circ$ |

In HSL, rotating the hue changes the perceived lightness a lot. In OKLCH it doesn't: rotate $h$, keep $L$, and the new hue looks equally light. Keep $C$ the same too, *if the gamut allows it*.

## The gamut gets in the way

Rotating our indigo ($L = 0.511$, $C = 0.230$) by $180^\circ$ lands on $h = 97^\circ$, a yellow. At that lightness, sRGB yellows only reach $C = 0.105$. The color is gamut-mapped to `#776600`: same lightness and hue, less than half the chroma, and an olive rather than a yellow.

| Rotation | Hue | After gamut mapping | Max $C$ at $L = 0.511$ |
|---|---|---|---|
| 0° | 277° | `#4f46e5` | 0.278 |
| +30° | 307° | `#8928c9` | 0.262 |
| −30° | 247° | `#006aae` | 0.134 |
| +120° | 37° | `#b23300` | 0.171 |
| 180° | 97° | `#776600` | 0.105 |

That's not a bug. It tells you that **a complementary color for an indigo will look lighter, or duller, than the indigo**. Let the accent have its own lightness (yellow accents work as light highlights, not as dark text).

## How much of each color: 60-30-10

A classic proportion is about 60% dominant color (neutral backgrounds), 30% secondary (surfaces and text) and 10% accent (brand and actions). In apps, the brand color is usually *less* than 10%. Its job is to point at the primary action, and it can only do that if it's rare.

## In code

```js
import { cssOklch, oklchToRgb, parseHex, rgbToOklch, toHex } from './color.js';

const base = rgbToOklch(parseHex('#4f46e5'));
const triad = [120, 240].map((d) => ({ ...base, h: (base.h + d) % 360 }));
triad.map((c) => toHex(oklchToRgb(c)));  // gamut-mapped: ['#b23300', '#007a49']
```
