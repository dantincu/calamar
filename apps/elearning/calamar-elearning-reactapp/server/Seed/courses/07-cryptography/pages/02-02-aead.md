# Authenticated encryption (AEAD)

An **AEAD** (authenticated encryption with associated data) cipher does encryption and integrity in one primitive:

$$
\operatorname{Seal}(K, N, P, A) \to (C, T), \qquad \operatorname{Open}(K, N, C, T, A) \to P \ \text{or} \ \bot
$$

- $K$: the key; $N$: the **nonce** (unique per message); $P$: the plaintext;
- $A$: **associated data**, authenticated but not encrypted: headers, message numbers, protocol versions;
- $T$: the authentication **tag**. If anything was changed ($C$, $T$, $N$ or $A$), $\operatorname{Open}$ fails with $\bot$, and returns **no plaintext at all**.

## AES-GCM

**Galois/Counter Mode** = CTR-mode encryption + **GHASH**, a polynomial hash over the field $\mathrm{GF}(2^{128})$:

- $H = E_K(0^{128})$ is the hash key;
- the AAD and ciphertext blocks $X_1, \dots, X_m$ (followed by a block holding their lengths) are combined as a polynomial evaluated at $H$:

$$
\operatorname{GHASH}_H(X) = X_1 H^m \oplus X_2 H^{m-1} \oplus \cdots \oplus X_m H
$$

- the tag is $T = \operatorname{GHASH}_H(A, C) \oplus E_K(J_0)$, where $J_0$ is the counter block derived from the nonce.

It's very fast with hardware support (AES-NI and carry-less multiplication), and it's the most widely used AEAD (TLS, IPsec, SSH, disk encryption).

## ChaCha20-Poly1305

**ChaCha20** is a stream cipher built only from 32-bit additions, rotations and XORs (an "ARX" design). It's fast and constant-time in plain software, even on devices without AES instructions. **Poly1305** is a polynomial MAC modulo the prime $2^{130} - 5$. Together they form the second AEAD of TLS 1.3, SSH and WireGuard.

## Try it

`aead.js` encrypts with both, then tampers:

```
aes-256-gcm: 51 bytes = 12 nonce + 23 ciphertext + 16 tag
  decrypts to: Transfer 100 EUR to Bob
  one flipped bit  -> Unsupported state or unable to authenticate data
  changed AAD      -> Unsupported state or unable to authenticate data
```

## The one rule: never repeat a nonce under the same key

Both AEADs use a keystream derived from $(K, N)$. Reuse a nonce, and:

1. **Confidentiality breaks**: $C_1 \oplus C_2 = P_1 \oplus P_2$. `aead.js` reuses a nonce, and recovers the second message from the first:

   ```
   Nonce reused. The attacker knows message 1, and computes C1 ^ C2 ^ P1:
     -> "The password is tiger-42!"
   ```

2. **Authenticity breaks** (for GCM): two tags under the same nonce give an equation in the hash key $H$, which an attacker can solve, and then **forge** messages at will.

How to get unique nonces:

| Strategy | Notes |
|---|---|
| **Counter** (0, 1, 2…) per key | simplest and safest when one sender holds the state: TLS and the project use it |
| **Random 96-bit** | fine up to about $2^{32}$ messages per key (birthday bound: $q^2/2^{97}$); `aead.js` prints the probabilities |
| **XChaCha20-Poly1305** (192-bit nonces) | random nonces with no practical limit |
| **AES-GCM-SIV** | "nonce-misuse resistant": a repeat leaks only whether two messages were identical |

## Using AEAD well

- **Keys**: 256-bit random keys (from a CSPRNG or a KDF), never passwords directly.
- **Put context in the AAD**: message number, sender, protocol version. Then a valid ciphertext can't be moved to another context.
- **Rotate keys** before the limits: about $2^{32}$ messages for random-nonce GCM, and well before $2^{64}$ blocks in any case.
- On failure, reveal nothing: no "bad padding" versus "bad tag" distinctions, and no partial plaintext.
