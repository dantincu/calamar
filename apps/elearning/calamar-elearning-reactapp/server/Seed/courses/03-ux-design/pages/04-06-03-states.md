# States and transparency

Every interactive element needs colors for several **states**: default, hover, pressed (active), focused, disabled and selected. There are two ways to produce them.

## 1. Move along the scale

```css
.button-primary              { background: var(--color-primary); }        /* brand-600 */
.button-primary:hover        { background: var(--color-primary-hover); }  /* brand-700 */
.button-primary:active       { background: var(--color-primary-active); } /* brand-800 */
```

Each step is visibly different ($\Delta E_{\text{OK}} \approx 0.07$), and the contrast with white text *rises* as the button darkens (4.6, then 6.2, then 8.5). It's simple and predictable, and it's what this course's tokens do.

## 2. Overlay a translucent color

Material-style "state layers" put a translucent black or white layer over the element. To know what the user sees, and so what its contrast is, use the **compositing formula**. A color $F$ with opacity $\alpha$ over an opaque background $B$ shows, per channel:

$$
C = \alpha\, F + (1 - \alpha)\, B
$$

Browsers apply it to the gamma-encoded channel values by default.

**Example.** 10% black over `#6060fb`, $(96, 96, 251)$, gives $0.9 \times (96, 96, 251) = (86.4, 86.4, 225.9)$, which is `#5656e2`. Its contrast with white text is 5.47:1, up from 4.6.

**Example.** 50% black over white is $0.5 \times 0 + 0.5 \times 255 = 127.5$ per channel, which is `#808080`. That's only 3.95:1, so `rgba(0, 0, 0, 0.5)` is **not** a valid body-text color on white, although it looks dark enough to many designers.

When the background behind a translucent element varies (images, gradients), check the worst case: the lightest background for dark overlays and the darkest for light ones.

## Mixing in CSS

```css
/* 10% black mixed into the primary, in a perceptual space */
.button-primary:hover { background: color-mix(in oklch, var(--color-primary), black 10%); }

/* or with relative color syntax: just lower the lightness */
.button-primary:hover { background: oklch(from var(--color-primary) calc(l - 0.06) c h); }
```

`color-mix(in srgb, …)` matches the compositing formula above, while `in oklch` mixes perceptually. Whichever you choose, the result needs the same contrast checks as any other color.

## Focus

The focus indicator must be visible against what's around it: at least 3:1 against the adjacent colors (WCAG 1.4.11; 2.4.13 in AAA also sets a minimum size). A 2–3 px outline in `--color-focus-ring` with a 2 px offset, so that it sits on the page background rather than on the button, is reliable:

```css
:focus-visible { outline: 3px solid var(--color-focus-ring); outline-offset: 2px; }
```

## Disabled

Disabled controls are exempt from contrast requirements, but users still need to *find* them and tell that they're disabled. Use a lower-contrast neutral (neutral-300 text on neutral-100), and don't rely on opacity alone: `opacity: 0.4` on a colored button produces a pastel that can look like a different, *enabled* button style.

## Selected

A selected row or tab needs more than a background tint. The tint (brand-50) differs from white by only 1.05:1. Add a bold label, a check mark or a 3:1 indicator bar.
