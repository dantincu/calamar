# Hardening sudo

`sudo` is a deliberate hole in the privilege wall, so its rules deserve the same review as firewall rules. The attached `deploy` file is a complete, commented `/etc/sudoers.d/` drop-in.

## Grant commands, not shells

```
Cmnd_Alias MYAPP = /usr/bin/systemctl restart myapp.service, \
                   /usr/bin/systemctl reload myapp.service
deploy ALL=(root) NOPASSWD: MYAPP
```

- Use **full paths**. A relative name would be looked up in a `PATH` that the user controls.
- Give **exact arguments**. `/usr/bin/systemctl restart myapp.service` allows exactly that, and `systemctl` with no arguments listed would allow *any* arguments.
- Run as a **specific user**: `(root)`, or better, the service's own user when that's enough.

## The shell-escape problem

Many ordinary programs can start other programs or write arbitrary files. If `sudo` lets a user run one of them as root, it hands them a root shell:

| Allowed command | Escape |
|---|---|
| `less`, `more`, `man` | type `!sh` inside the pager |
| `vim`, `nano` | `:!sh`, or edit `/etc/sudoers` itself |
| `find` | `-exec /bin/sh \;` |
| `tar`, `zip`, `rsync`, `git` | options that run commands |
| `cp`, `tee`, `dd` | overwrite `/etc/passwd` or `/etc/sudoers` |
| `python`, `perl`, `awk` | interpreters: anything |

The catalogue of such techniques is public (GTFOBins), and attackers check every `sudo -l` they find against it. Safe rules allow programs that do **one fixed thing**. For editing, use `sudoedit` (`sudo -e`), which edits a copy as the user and installs it as root.

Also, never allow a script that the user can modify (in their home, or in a writable directory). They would just change it.

## Defaults worth setting

```
Defaults use_pty                       # commands get their own terminal
Defaults logfile="/var/log/sudo.log"   # a dedicated log
Defaults timestamp_timeout=5           # re-ask the password after 5 minutes
Defaults secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
```

## Installing rules safely

```bash
$ sudo visudo -cf deploy                     # check the syntax first
$ sudo install -m 0440 -o root -g root deploy /etc/sudoers.d/deploy
$ sudo -l -U deploy                          # what can deploy run now?
```

Files in `/etc/sudoers.d/` whose names contain a `.` or end in `~` are **ignored**. `deploy.conf` would silently do nothing.

## Review regularly

```bash
$ sudo grep -rE 'NOPASSWD|ALL *= *\(ALL' /etc/sudoers /etc/sudoers.d/
$ getent group sudo wheel admins
```

Every entry should have an owner and a reason. Remove people from admin groups when they change roles.
