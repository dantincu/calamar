# Acting as root with sudo

Logging in as root is risky: every typo runs with unlimited power, and the logs can't tell *which* administrator did what. **sudo** runs single commands as root (or as another user) and logs each one.

```bash
$ sudo apt update                 # one command as root; asks for YOUR password
$ sudo -i                         # an interactive root shell (use sparingly)
$ sudo -u postgres psql           # as another user
$ sudo -l                         # what am I allowed to run?
$ sudo !!                         # rerun the previous command with sudo
```

After you enter your password, sudo remembers it for a few minutes (the default is 15 on most distros).

## Who may use sudo

Rules live in `/etc/sudoers` and in files under `/etc/sudoers.d/`. On Debian and Ubuntu, members of the `sudo` group may run anything; on the Red Hat family, it's the `wheel` group:

```
%sudo   ALL=(ALL:ALL) ALL
```

That reads: members of group `sudo`, on ALL hosts, may run as ALL users and ALL groups, ALL commands.

**Always edit with `visudo`**, which checks the syntax before saving. A syntax error in sudoers can lock every administrator out:

```bash
$ sudo visudo                         # the main file
$ sudo visudo -f /etc/sudoers.d/deploy  # a drop-in file
```

## Limiting what a user may run

```
# the deploy user may restart one service, and nothing else, without a password
deploy  ALL=(root) NOPASSWD: /usr/bin/systemctl restart myapp.service
```

Be careful: allowing a program that can start other programs (an editor, `less`, `find`, `tar`…) effectively allows *everything*. The security course covers this.

## Redirection and sudo

```bash
$ sudo echo "nameserver 1.1.1.1" > /etc/resolv.conf   # fails: the redirection is done by YOUR shell
$ echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf > /dev/null   # works: tee runs as root
$ echo "extra line" | sudo tee -a /etc/hosts       # -a appends
```

## Where it's logged

```bash
$ sudo journalctl _COMM=sudo       # systemd journal
$ sudo grep sudo /var/log/auth.log # Debian/Ubuntu
$ sudo grep sudo /var/log/secure   # Red Hat family
```
